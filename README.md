# PLATEAU 交通空白地可視化・施策シミュレーション（藤沢市北部）

- **公開デモ**: https://plateau-transit-poc.vercel.app/
- **開発形態**: PLATEAU AWARD 2026 自治体共創部門（藤沢市都市計画課 × 矢後敦 共同チーム）
- **技術スタック**: Next.js 16 (App Router) + TypeScript + CesiumJS + Web Worker + Vercel

CesiumJS で Project PLATEAU の3D建物モデル（LOD1）・地形を表示し、藤沢市北部の丘陵地・住宅団地（湘南大庭・遠藤・御所見地区など）における交通空白地の可視化と、追加停留所・モビリティ・ハブ施策の効果比較を行うWebアプリケーションです（Cesium ion アカウント・トークン不要）。

---

## 主な機能と特長

### 1. 住居単位の交通空白地可視化（3段階色分け）
藤沢市北部の評価基準（**バス停400m／鉄道駅800m**）を参考に、PLATEAUの建物属性（`bldg:usage`）から**住宅系建築物（住宅・共同住宅・店舗等併用住宅等）のみ**を自動抽出し、地形勾配を加味した実効歩行距離によって建物を色分けします。

- **緑（カバー率 ≦ 1.0倍）**: 基準圏内でカバーされている住宅
- **薄ピンク（1.0倍 ＜ カバー率 ≦ 1.5倍）**: 空白地（僅かに超過／施策で救済しやすい予備軍）
- **濃い赤（カバー率 ＞ 1.5倍）**: 空白地（非常に遠い／重点対策エリア）
- **白**: 住宅系以外の建物（倉庫・工場・純商業施設等）および未評価・道路網未収録建築物

### 2. 実効歩行距離の計算ロジック（坂道勾配・体力差の考慮）
単なる地図上の平面直線距離ではなく、国土地理院の数値標高モデル（DEM5A・5mメッシュ由来）から算出した道路・経路の斜度（勾配）をもとに、以下の計算式で歩行負担を距離換算しています。

```text
実効歩行距離 ＝ 水平距離 × [ 1 ＋ (① 勾配ペナルティ係数) × (② 方向割増倍率) × 斜度 ]
```

- **① 勾配ペナルティ係数（人の体力差）**:
  - **一般（標準の坂道補正）**: `3.0`（基準歩行速度 67m/分）。運動生理学のエネルギー消費研究（METs）およびGISの標準歩行速度モデル（Toblerの歩行関数等）において「斜度10%登坂時、平地比約1.4倍のエネルギーと時間を要する」知見から逆算して設定。
  - **高齢者（坂道の負荷係数2倍）**: `6.0`（基準歩行速度 50m/分）。運動生理学・リハビリテーション分野等の研究において「高齢者の坂道登坂時のエネルギー消費や筋力負荷が若年成人の約1.8〜2.2倍に跳ね上がる」知見を参考に一般の2倍に設定。
- **② 方向割増倍率（上り・下りの過酷さ）**:
  - **上り坂**: `1.25倍`（都市交通計画の歩行者行動研究における坂道敬遠係数 1.2〜1.3倍に基づく設定）
  - **下り坂**: `1.0倍`

画面左パネル内の「ℹ️ 計算のしくみ」ボタンから、利用者向けの解説モーダルを確認できます。

### 3. エリア対策シミュレーション（停留所の自由配置）
地図上の道路沿いをクリックするだけで仮設停留所（`#1`, `#2`, ...）を複数配置できます。
- ブラウザのバックグラウンド（Web Worker）上で **二分ヒープを用いたダイクストラ法（計算量 $O(E \log V)$）** を実行し、クリックした道路区間上の投影点（エッジ分割補間）から周囲の全住宅への最短実効距離を即座に再計算します。
- 新たにカバー圏内に入った住宅を**水色**でハイライトし、新規カバー棟数・延床面積・深刻空白地の削減数・停留所ごとの単独貢献度を集計します。
- 実効距離基準の緩和倍率スライダーによる感度分析、および結果の **GeoJSON エクスポート**（QGIS等の既存GIS連携）が可能です。

### 4. モビリティ・ハブ実証検討シミュレーション
藤沢市より提供された4箇所の実証検討候補地（H1〜H4：湘南大庭・遠藤地区）をもとに、既存のバス停では届かない空白地住宅の救済効果を拠点ごとに個別設定・試算できます。
- 各ハブに対して **シェアサイクル（400m〜1.5km）／電動キックボード（400m〜1.5km）／カーシェア・小型EV（1km〜3km）／自由設定** を独立して切り替え、全体の救済棟数・延床面積をリアルタイムに算出します。
- 救済結果の GeoJSON エクスポート機能を備えています。

### 5. 距離モデル（直線距離／道路網距離）と高速化技術
画面左パネルの「距離モデル（直線／道路網・クリックで詳細）」から、2つの距離計測モデルを切り替え可能です。
- **直線距離モデル**: 建物〜最寄りのバス停・駅を結ぶ直線上の地形標高をサンプリングし、勾配負荷を加味して評価。
- **道路網距離モデル**: OpenStreetMapから構築した **320,444ノード・342,162本** の歩行道路グラフ上で最短ルートを探索し、各道路区間の勾配負荷を積算して評価（道路迂回を考慮し、基準1.2倍＝バス480m／駅960mを標準適用）。
- **事前計算データベース化**: 対象エリアの住宅系建物 **78,542棟** 分の初期評価スコアを事前計算して静的データベース（`public/data/building-network-scores.json`）に集約しているため、アクセス時やプロファイル切替時にもサーバー負荷ゼロで数万棟を瞬時に色分け描画できます。

### 6. 地名ラベル・逆ジオコーディング・シェアサイクル連携
- 藤沢市北部の駅・地区名・ランドマーク221箇所（Overpass APIより抽出）を常時ラベル表示。
- 候補地点クリック時はNext.js API Route（`/api/reverse-geocode`）経由で推定地区名を逆ジオコーディング表示。
- ODPTセンターのGBFSデータを用いたハローサイクリングステーションのリアルタイム表示（`/api/hellocycling-stations`）に対応。

## セットアップ（ローカル起動）

```bash
npm install
npm run dev
```

ブラウザで `http://localhost:3000` を開いてください。
スマートフォン実機からLAN経由で確認したい場合は、`next.config.ts` の `allowedDevOrigins` にご自身の環境のLAN IPパターンが含まれているか確認してください（デフォルトで `192.168.*.*` と `10.*.*.*` をカバー済み）。

### 必須・任意の環境変数
ハローサイクリングステーション表示（`/api/hellocycling-stations`）を使用する場合は、ODPTセンターのアクセストークン `ODPT_CONSUMER_KEY` を `.env.local` に設定してください（`.env*` は `.gitignore` 対象）。Vercel環境では `vercel env add ODPT_CONSUMER_KEY production` 等で設定します。未設定でも本体機能（交通空白地可視化・シミュレーション）には影響ありません。

## データ出典と技術構成

### 交通施設・地理データについて
- **3D都市モデル・オルソ画像・地形**: Project PLATEAU（藤沢市 `14205` LOD1建物3D Tiles、PLATEAU-Ortho、PLATEAU-Terrain）
- **バス停データ（`public/data/bus-stops.json`）**: 国土数値情報「バス停留所データ」（P11、第3.0版、令和4年度）から抽出したデータ（地図表示337件／分析対象：神奈川中央交通等の周辺矩形765停留所）。
  - *注記*: 2022年度作成データのため、それ以降の路線改廃は一部未反映の可能性があります。また、デマンドバス・高速バスは製品仕様上含まれません。
- **鉄道駅データ**: OpenStreetMap座標および国土数値情報N02（2022年度）の駅ホーム形状重心。
- **道路ネットワーク（`public/data/routing-graph.json`）**: OpenStreetMapの歩行可能道路網および国土地理院 DEM5A（5mメッシュ標高）。生成手順は `scripts/road-network/README.md` を参照。
- **シェアサイクル（ハローサイクリング）**: ODPTのGBFSデータ（ライセンス：CC BY 4.0 / ODC BY 1.0 / ODbL 1.0、提供者：OpenStreet株式会社 / 公共交通オープンデータ協議会）。

### 仕組みのポイント
- **SSR無効化**: Cesium は DOM/`window` に依存するため、`app/page.tsx` にて `next/dynamic`（`ssr: false`）でクライアントマウントしています。
- **Next.js 16 Webpack設定**: Cesium の静的アセット（Workers/Assets/Widgets）を `copy-webpack-plugin` で配信する都合上、`dev` / `build` は `--webpack` フラグで実行し、`terser-webpack-plugin` にてCesiumバンドルの再minify競合を回避しています（`next.config.ts`）。
- **Cesium標準UIとの競合回避**: 独自の建物・バス停・シミュレーションポップアップUIを実装するため、Viewer初期化時に Cesium 標準の `infoBox` / `selectionIndicator` を無効化しています。
