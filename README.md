# PLATEAU 交通空白地 PoC (Next.js + TypeScript + CesiumJS)

PLATEAU CityHack Challenge 2026 向けのPoCです。CesiumJS で PLATEAU の建物3D Tiles（LOD1）・地形を表示します。テーマは「藤沢市北部の交通空白地」（公共交通が手薄なエリアの可視化）です。姉妹プロジェクト`plateau-poc`（江の島・津波避難テーマ）で得た知見を最初から適用しています。Cesium ion のアカウント・トークンは不要です。

**現状の実装**: 建物3D Tiles・地形・オルソ画像に加え、藤沢市北部（JR東海道線より北側）のバス停ピン（337件）、住宅系建物の「藤沢市公式基準による交通空白地」色分け表示、そして**デマンド交通乗り場候補の自動提案**ができます。住宅系建物（`bldg:usage`に「住宅」を含むもの）ごとに最寄りバス停・最寄り鉄道駅それぞれまでの実効距離（標高差・勾配を考慮した歩行負荷）を計算し、藤沢市公式の交通空白地判定基準（**鉄道駅600m圏 or バス停300m圏**、メンター自治体への確認で判明）に基づいて緑（カバーされている）〜赤系2段階（空白地、超過度合いのグラデーション）で建物3D Tilesを色分けします。建物をクリックすると判定結果・最寄りバス停/駅それぞれの実効距離・徒歩時間目安をポップアップ表示します。画面左下にはリアルタイムの建物カバー率と、事前計算した面積カバー率を藤沢市公式資料の数値（78%）と並べて表示します。さらに、この公式基準でカバーされていない建物の座標をk-meansでクラスタリングし、クラスタ重心を紫の四角ピンで「新しい乗り場を置くならここ」として提案します（クリックで対象建物数・現状の平均実効距離・新設した場合の推定実効距離・逆ジオコーディングによる推定地区名を表示）。地図上の位置把握を助けるため、主要な駅・地名も常時ラベル表示しています。鉄道駅の「ピン」（丸マーカー）はまだ実装していませんが、判定計算には駅データを組み込み済みです（詳細は`AGENTS.md`の「次にやるべきこと」参照）。

## セットアップ

```bash
npm install
npm run dev
```

`http://localhost:3000` を開くと、バス停群の重心付近（固定半径900m）にフィットしたカメラで建物3Dモデルが表示されます。数秒待つと、色分けされた建物が画面いっぱいに表示されます。バス停ピンをクリックすると停留所名がポップアップ表示されます。

**バス停データについて（正式決定）**: このハッカソン（開発期間 2026年8月22日〜9月5日）では、神奈川中央交通の公式GTFS-JPが以下の理由で入手できないため、代わりに国土数値情報「バス停留所データ」（P11、第3.0版、**データ作成年度2022年度（令和4年度）**）から抽出したデータ（`public/data/bus-stops.json`）を採用しています：

1. ODPTセンターの通常アクセストークンでは、神奈川中央交通のデータセットは提供対象外（「公共交通オープンデータチャレンジ限定ライセンス」下にあり、センター用の一般トークンでは取得できない）
2. チャレンジ専用トークンは「公共交通オープンデータチャレンジ2026」への参加登録で発行されるが、申込期間が2026年10月1日〜2027年1月11日であり、開発期間に間に合わない

国土数値情報P11データには以下の制約があります（製品仕様書に明記）:

- **2022年度（令和4年度）作成のデータのため、それ以降の路線改廃・停留所の新設/廃止が反映されていない可能性があります**
- **デマンドバス（予約制）・高速バス（都市間・長距離輸送目的）は整備対象から除外**されており、本データには含まれません

既存の津波浸水想定データ（国土数値情報A40）と同じ国土数値情報の提供データであり、扱いは同様です。詳細は`AGENTS.md`の「バス停データについて」を参照してください。

スマートフォン実機からLAN経由で開発サーバーを確認したい場合は、`next.config.ts`の`allowedDevOrigins`に自分の環境のLAN IPパターンが含まれているか確認してください（デフォルトで`192.168.*.*`と`10.*.*.*`をカバー済み）。

## 対象エリアを変える

`app/PlateauViewer.tsx` 先頭の自治体コードを書き換えるだけです。

```ts
const CITY_CODE = "14205"; // 総務省の全国地方公共団体コードに差し替え
```

自治体コードは総務省の「全国地方公共団体コード」一覧（https://www.soumu.go.jp/denshijiti/code.html）で調べられます。

`BUILDING_TILESET_URL` は `{自治体コード}-bldg-lod1-latest` の形式で組み立てているため、コードを変えるだけで別自治体の最新データに切り替わります。LOD2（テクスチャ付き詳細モデル）を使いたい場合は `datacatalog/plateau-datasets` API のレスポンスから該当自治体の `composite_url` を確認して直接差し替えてください。

カメラの初期位置（`INITIAL_VIEW`）も対象エリアに合わせて書き換えてください。

## 藤沢市公式基準による交通空白地の可視化について

メンター自治体（藤沢市）に確認したところ、公式の交通空白地の定義は「鉄道駅から600m圏、バス停から300m圏（高齢者の移動を考慮した基準）に入らないエリア」とのことでした。この定義に基づいて、住宅系建物を「カバーされている」「交通空白地」に判定・色分けしています。

PLATEAU LOD1建物3D Tilesのバッチテーブルには、実は各建物の重心座標（`_x`/`_y`）・用途（`bldg:usage`）・延床面積（`uro:BuildingDetailAttribute_uro:totalFloorArea`）がフィーチャー単位で含まれています。これを`Cesium3DTileFeature.getProperty()`で直接取得し、以下の流れで住宅系建物を色分けしています：

1. 住宅系（`bldg:usage`に「住宅」を含む）かつ藤沢市北部の建物を対象に絞る
2. **主要事業者（神奈川中央交通、297件）のバス停**、および**鉄道駅（5駅）**それぞれとの直線距離（Haversine）で最寄りを検索（詳細は`AGENTS.md`参照）
3. 建物〜最寄りバス停・建物〜最寄り駅、それぞれの直線を5点サンプリングし、`Cesium.sampleTerrainMostDetailed`で標高を取得
4. 区間ごとの勾配に応じて直線距離を割り増しした「実効距離」を、バス・駅それぞれについて計算（シンプルな線形モデル）
5. `カバー率 = min(バス実効距離/300, 駅実効距離/600)` を計算し、1以下なら「カバーされている」（緑）、1超なら「交通空白地」として超過度合いに応じ赤系2段階（1.5倍で区切り）に色分け

地図上のバス停ピンは337件全体を表示していますが、主要事業者（神奈川中央交通）のみ大きく不透明なピン、それ以外（コミュニティバス等）は小さく半透明なピンで区別しています。判定計算に使われるのは前者のみです（鉄道駅は5駅すべてを対象にしています）。

**カバー率の実測値**: 画面左下のパネルで、読み込み済み建物ベースのリアルタイム建物カバー率と、事前計算した面積カバー率（格子点分析、約72%）を、藤沢市公式資料の数値（面積カバー率78%、藤沢市**全域**）と並べて確認できます。本PoCは藤沢市**北部**（交通の便が比較的悪いエリア）に絞って可視化しているため、市全域の数値よりやや低めに出ること自体は想定内です。詳細・手法上の限界は`AGENTS.md`の「藤沢市公式基準による交通空白地の可視化について」を参照してください。

処理対象は最大20000件（`MAX_SCORED_BUILDINGS`）に制限しています。全建物を無制限に処理すると地形サンプリングの呼び出しが増えて重くなるためです（この上限はグローバル・恒久的なので、低すぎると特定エリアだけ永久に色分けされなくなる不具合を招いたことがあります。詳細は`AGENTS.md`の「藤沢市公式基準による交通空白地の可視化について」参照）。

**確認する際の注意**: 初期カメラは900m半径にフィットするため、開いた直後から色分けされた建物が画面いっぱいに見えますが、タイル読み込み・地形サンプリングが追いつくまで数秒かかります。ページを開いて数秒待ってから確認してください。他のエリアを見たい場合はズームアウト/パンしてください。

## 勾配・歩行速度プロファイル（一般/高齢者）について

画面左上のLegendのラジオボタンで、勾配への感度・歩行速度を「一般」「高齢者（坂道に配慮）」の2プロファイルから切り替えられます。切り替えると、建物の色分け・徒歩時間・デマンド交通乗り場候補がすべて新しいプロファイルで再計算されます（藤沢市北部が高齢化率の高いエリアであることを踏まえた機能）。

- 一般: 勾配ペナルティ係数3、歩行速度は分速67m（時速4km）
- 高齢者（坂道に配慮）: 勾配ペナルティ係数6（一般の2倍）、歩行速度は分速50m（時速3km、バリアフリー設計の参考値）

**注記**: これらの係数は医学的・工学的な実測値に基づくものではなく、あくまで目安です。詳細・実装方式（プロファイル切り替え時の再計算がどう行われるか）は`AGENTS.md`の「勾配・歩行速度プロファイル（一般/高齢者）について」を参照してください。

## デマンド交通乗り場候補について

藤沢市公式の交通空白地判定でカバーされていない（カバー率の超過倍率が既定1.0倍超）住宅系建物の座標に、依存関係を追加せず自前実装した簡易k-means（既定k=4、決定的な初期化）でクラスタリングをかけ、クラスタ重心を紫の四角ピンで表示します。新しいデータソースは使わず、既存の`buildingScoreCache`（色分け計算の結果）をそのまま流用しています。超過倍率の閾値（1.0〜3.0倍。デフォルト1.0倍は公式基準にちょうど一致）とクラスタ数（1〜10件）は画面左上のスライダーで自由に調整できます。

候補地点をクリックすると、対象建物数・現状の平均実効距離（バス基準）に加えて、「もしここに乗り場を新設したら」の推定実効距離を、色分け計算と全く同じロジック（目的地を既存バス停群からクリックした候補地点に差し替えるだけ）で再計算して表示します。建物が既にスコア計算されるたびに（デバウンス付きで）再クラスタリングするため、ズーム・パンして新しいエリアの建物が読み込まれると候補ピンの位置も変わっていきます。詳細な設計・既知の制約は`AGENTS.md`の「デマンド交通乗り場候補について」を参照してください。

## 地名ラベル・逆ジオコーディングについて

土地勘のない判定員・自治体職員でも地図上の位置関係を把握できるよう、2つの補助表示を実装しています。

1. 藤沢市北部の駅・地区名・ランドマーク（学校・神社仏閣・公園）221箇所（Overpassから抽出）を、クリック不要の常時表示テキストラベルとして地図上に表示します。
2. デマンド交通乗り場候補（紫の四角）をクリックした際のポップアップに、クラスタ重心の座標をNominatimで逆ジオコーディングした「推定地区名」を表示します。逆ジオコーディングはレート制限・利用規約上の`User-Agent`要件を踏まえ、クライアントから直接叩かずNext.jsのAPI Route（`/api/reverse-geocode`）経由でサーバー側から呼び出しています。

詳細は`AGENTS.md`の「地名ラベル・逆ジオコーディングについて」を参照してください。

## ハローサイクリング ステーション表示について

藤沢市北部エリアの、ハローサイクリング（OpenStreet株式会社のシェアサイクル）ステーション位置を黄色い自転車ピンで表示します。クリックするとステーション名・収容可能台数（GBFSの`capacity`属性）をポップアップ表示します。**現段階では表示のみで、交通空白地の色分けロジックには組み込んでいません。**

**データ出典・ライセンス**: ODPT（公共交通オープンデータセンター）のGBFS形式データ（`https://api.odpt.org/api/v4/gbfs/hellocycling/station_information.json`）。

- ライセンス: **CC BY 4.0 / ODC BY 1.0 / ODbL 1.0**（[データカタログ](https://ckan.odpt.org/dataset/c_bikeshare_gbfs-openstreet)の記載に従う）
- コンテンツ等の提供者名: **OpenStreet株式会社 / 公共交通オープンデータ協議会**
- このデータは常時公開データであり、バス停のGTFS-JPと異なり「公共交通オープンデータチャレンジ2026限定ライセンス」の対象外。ODPTセンターの通常アクセストークンで取得できる

**必須の環境変数**: `ODPT_CONSUMER_KEY`（ODPTセンターのアクセストークン）。`.env.local`に設定してください（`.env*`は`.gitignore`済みでコミットされません）。Vercelにデプロイする場合は`vercel env add ODPT_CONSUMER_KEY production`等で別途設定が必要です。未設定の場合、`/api/hellocycling-stations`が500を返しますが、他の機能（バス停・建物色分け等）には影響しません（ステーションピンが表示されないだけです）。

**藤沢市北部エリアへの絞り込みについて**: GBFSは全国のステーションを一括で返すデータのため、`/api/hellocycling-stations`（サーバー側）でバウンディングボックス＋東海道線より北かどうかの判定により絞り込んでいます。藤沢市の行政境界ポリゴンそのものは使っていない簡易フィルタのため、隣接自治体の一部が含まれる可能性があります。詳細は`app/api/hellocycling-stations/route.ts`のコメント参照。

## 道路網距離モデル（実験的機能）について

画面左上のLegendに「距離モデル（実験的機能・クリックで詳細）」という折りたたみ項目があります（既定で閉じています）。展開すると、既存の直線距離モデル（デフォルトの判定基準）と、道路ネットワーク上の経路距離で判定し直した道路網距離モデルを、ブラウザ上で切り替えて見比べられます。

**位置づけ**: メンター自治体（藤沢市、丹野氏）からの「直線距離ではなく道路ネットワーク上の経路距離で交通空白地を判定すべきでは」という提案を検証するための、藤沢市への報告用の比較機能です。あくまで視覚比較用の実験的機能であり、本採用の判断は別途行います（本体の判定基準は今後も直線距離モデルのままです）。「道路網距離」に切り替えると、直線距離モデルでは基準を満たしていた建物のうち実際にはどれだけが交通空白地に転じるか（見落としていたニーズ）を確認できます。

**実装メモ**: 道路網距離は`scripts/road-network/`のオフラインパイプライン（osmnxで取得した道路網上でダイクストラ法により最短経路を計算）で事前計算したもので、`public/data/building-network-scores.json`（44.5MB）に格納されています。このファイルはページの初期表示では読み込まれず、Legendで「道路網距離」を選択した瞬間に初めて遅延フェッチされます（直線距離モデルしか使わない場合は一切ダウンロードされません）。パイプラインの詳細・比較検証結果（カバー率48.1%→49.9%、見落としていたニーズ26.8%等）は`scripts/road-network/README.md`を参照してください。

## 仕組みのポイント

- **地形**: `tile.plateauview.mlit.go.jp` の PLATEAU-Terrain を利用（Cesium ion 不要）
- **建物**: `api.plateauview.mlit.go.jp` の複合 tileset.json API を利用。`-latest` サフィックスで新年度データに自動追従
- **Next.js対応**: Next.js 16 はデフォルトで Turbopack のため、Cesium の静的アセット（Workers/Assets/Widgets）をコピーする `copy-webpack-plugin` を使う都合上、`dev`/`build` は `--webpack` フラグ付きで実行するようにしている（package.json 参照）。コピー先は `next dev`/`next build` の出力先の違いを避けるため `process.cwd()` 基準の絶対パスにしている（`next.config.ts`）
- Cesium は DOM/window に依存するため、`app/page.tsx` で `next/dynamic` の `ssr: false` を使ってクライアントのみで読み込んでいる
- Cesium標準の `infoBox`/`selectionIndicator` はViewer初期化時に無効化済み（バス停等の独自UIを実装した際に競合しないようにするため）
- 本番ビルド限定でCesiumバンドルがNextの内蔵minifierと衝突する既知の問題（詳細は`AGENTS.md`）に対応するため、`terser-webpack-plugin`でCesiumを再minify対象から除外する設定を最初から入れてある
